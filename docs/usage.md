# Работа с библиотекой

## Рабочая область и чтение

`DbfHarbour` — низкоуровневый статический API. `UseReadOnly` открывает таблицу без права записи на уровне Harbour RDD; `Use` открывает её для записи. Аргумент `exclusive: true` запрашивает эксклюзивное открытие; `false` — совместное. Алиас идентифицирует рабочую область Harbour. Закрывайте её через `CloseArea(alias)` в `finally`, как в примере README.

Записи имеют физические номера начиная с 1. `GoTo`, `Skip`, `ActiveRecord`, `TotalRecords`, `EndOfFile`, `GetValues` и `GetValuesRange` работают с текущей областью. `GoTo` принимает номера от 0 до `UInt32.MaxValue`; счётчики и блокировка записи в текущем API используют `int`, поэтому полная поддержка таблиц с более чем 2³¹ записями не подтверждена. Переход за последнюю запись не является чтением существующей записи: перед изменением убедитесь, что нужная запись найдена.

Harbour VM и её настройки имеют общее состояние. Вызовы выполняются последовательно на одном внутреннем потоке, где VM инициализируется и завершается. При нескольких рабочих областях явно выбирайте нужный алиас через `SelectArea`: отдельные низкоуровневые вызовы других потоков могут выполняться между выбором области и следующей операцией. Объедините зависимую последовательность в одну операцию через `DbfRuntime.ExecuteAsync(() => { ... })` или используйте типизированный API. Внешний код, который вызывает нативную DLL напрямую или меняет настройки и блокировки во время работы библиотеки, не координируется с очередью.

До первого обращения к VM можно вызвать `DbfRuntime.Configure(queueCapacity: 256)`. По умолчанию очередь вмещает 256 ожидающих операций, не считая выполняемой. `ExecuteAsync` асинхронно ждёт свободное место и принимает `CancellationToken` для отмены этого ожидания; после постановки отмена не прерывает выполняемую операцию. Ограничение не уменьшает число задач, заранее созданных вызывающим кодом. Делегат должен быть синхронным; повторная постановка из потока исполнителя отклоняется. Не ожидайте из делегата другую операцию этой очереди. `DbfRuntime.Shutdown()` завершает уже принятые операции, закрывает оставшиеся сеансы и рабочие области, затем останавливает VM; повторный запуск в том же процессе не поддерживается. При выходе из процесса выполняется автоматическое завершение. Требуется пересобрать и доставить управляемую и нативную DLL из одной версии исходников.

## Изменение записи

`Beta.Database` — более удобная, но экспериментальная обёртка с `IDisposable`. Следующий фрагмент относится к **копии** `basic.dbf` вместе с FPT и обоими CDX; значения записываются в CP866:

```csharp
using System;
using System.Collections.Generic;
using System.IO;
using System.Text;
using HarbourDBF.NET;
using HarbourDBF.NET.Beta;

using (var db = new Database(Path.Combine(dir, "basic.dbf"), exclusive: true, codepage: "UA866")
       { DatabaseEncoding = Encoding.GetEncoding(866) })
{
    db.RegisterIndex("ID", Path.Combine(dir, "basic_id.cdx"));
    db.RegisterIndex("NAME", Path.Combine(dir, "basic_name.cdx"));
    using (db.MakeLock(2))
    {
        db.SetValues(2, new Dictionary<string, object> {
            { "NAME", "Ёлка" }, { "BIRTH", new DateTime(2001, 2, 3) },
            { "NOTE", "Привет, memo!" }
        });
        DbfHarbour.Commit();
    }
}
```

`dir` — каталог копии с этими файлами. `MakeLock` снимает блокировку при выходе; при совместной записи блокируйте изменяемую запись и обрабатывайте неудачную блокировку. Для добавления используйте `DbfHarbour.Append()`, затем `ActiveRecord` и `db.SetValues(...)`. `Delete()` помечает текущую запись удалённой, `Recall()` снимает пометку; они не уменьшают число физических записей. `Commit()` записывает изменения, но не создаёт транзакцию с откатом.

## Индексы CDX

`Indexes.Load(path)` подключает существующий файл, `Indexes.Select(tag)` или `Select(number)` выбирает порядок, `Seek` выполняет поиск и устанавливает текущую запись. Поддерживаются перегрузки для `int`, `double`, `string`, `bool`, а также `SeekDate` и `SeekTimestamp`. Для строки задайте ту же кодировку, что используется данными. Для timestamp передавайте значение с точностью до миллисекунды. `softSeek` и `findLast` передаются Harbour; проверяйте возвращённый `bool` до чтения результата.

`Beta.Database.RegisterIndex` подключает файл и связывает его с именем для `Search`; его `Search` сейчас принимает только `int`. Для других ключей используйте `DbfHarbour.Indexes`, предварительно выбрав область `db.Alias`. Индексное выражение, сортировка, состав тегов и настройки RDD влияют на результат. Примеры показывают два отдельных CDX на таблицу; они не подтверждают произвольные выражения, многотеговые CDX и все варианты `UNIQUE`/`FOR`.

Например, если `db` — открытый `Beta.Database` для `special.dbf` и файл `special_time.cdx` уже подключён через `RegisterIndex`, поиск timestamp выглядит так:

```csharp
DbfHarbour.SelectArea(db.Alias);
DbfHarbour.Indexes.Select("STAMP");
var key = new DateTime(2026, 1, 1, 12, 0, 1, 123);
if (DbfHarbour.Indexes.SeekTimestamp(key))
    Console.WriteLine($"Номер записи: {DbfHarbour.ActiveRecord}");
```

При записи через Harbour RDD открытые индексы сопровождаются движком. Не открывайте только часть индексов, если остальные также должны оставаться актуальными. Не перестраивайте индексы перед проверкой корректности записи: это может скрыть ошибку.

## Ошибки и границы проверок

Ошибки Harbour обычно передаются как `HarbourException`; некорректные аргументы также могут вызвать исключения .NET. При ошибке записи транзакционного отката нет — проверяйте состояние данных и не продолжайте работу с непроверенной копией. Разные варианты кодировок, длительная конкуренция и конкретная CRM требуют отдельных испытаний. x64 и работа по SMB в текущем наборе не подтверждены.
