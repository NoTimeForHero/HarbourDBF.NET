# Типы и значения

Таблица описывает библиотеку и проверенные сценарии, а не все варианты форматов DBF. Набор примеров использует Harbour DBFCDX, CP866 и сортировку UA866. В `GetValues` передача результата идёт через JSON Harbour и Newtonsoft.Json: тип значения в C# зависит от типа и значения поля.

| DBF | Назначение | Что возвращает `GetValues` в проверенных примерах | Запись и ограничения |
| --- | --- | --- | --- |
| `C` | Строка фиксированной длины | `string` с пробелами справа | Передать `string`; кодировка значений должна соответствовать таблице. `Beta.Database.TrimText` по умолчанию удаляет пробелы с обоих концов. |
| `N` | Число | Целое обычно `Int64`, дробное — `Double` | Передать число соответствующего размера и точности. Денежные значения и границы представимости нужно проверять для конкретной схемы. |
| `D` | Дата | Строка `yyyyMMdd`; пустая дата возвращается пустым представлением | `Beta.Database.SetValues` принимает `DateTime` или `null` для пустой даты; время в `DateTime` для поля `D` не записывается. |
| `L` | Логическое | `bool` | Передать `bool`. |
| `M` | Memo | `string`; данные примера находятся в FPT | Передать `string`; FPT должен находиться рядом с DBF. В примерах проверен DBFFPT. |
| `@` | Timestamp Harbour | Строка `yyyyMMddHHmmssfff`; пустой timestamp — `00000000000000000` | Через `Beta.Database.SetValues` передать `DateTime` с точностью не выше миллисекунды или `null`. Часовой пояс не преобразуется и не хранится. |
| `+` | Автоматический номер | Число, в примере `Int64` | Значение формирует Harbour при добавлении. Проверены небольшие счётчики; произвольные схемы и граничные значения здесь не подтверждены. |
| `=` | Автоматическое время изменения | Строка timestamp | Значение формирует Harbour при записи; время зависит от часов машины. |
| `^` | Версия записи | Число, в примере `Int64` | Счётчик поддерживает Harbour; пример проверяет увеличение после изменения. Полный диапазон счётчика не проверен. |

`T` длиной 8 байт также обрабатывается Beta как timestamp при передаче `DateTime`/`null`; самостоятельный пример использует именно Harbour-поле `@`. Поддержку других типов, диалектов или произвольной точности не следует выводить из этой таблицы без дополнительной проверки.

## Важное различие API

`Beta.Database.SetValues` смотрит на схему поля и преобразует `DateTime` и `null` для `D`, `@` и `T`. В низкоуровневом `DbfHarbour.SetValues` такого преобразования нет; метод не принимает `null` и не должен использоваться для записи `DateTime` без явной проверки подходящего представления. При чтении оба API возвращают значения `GetValues` как `object`, а не автоматически преобразуют даты в `DateTime`.

Строки, возвращаемые из `Beta.Database`, по умолчанию обрезаются с обеих сторон (`TrimText = true`); для сохранения пробелов установите `false`. `IntInsteadLong = true` преобразует `Int64` в `Int32` и может вызвать переполнение. `GetValue<T>` применяет `Convert.ChangeType`, если значение ещё не имеет типа `T`: для точного контроля типа используйте `GetValues`.

Кодировка на двух уровнях задаётся отдельно: `codepage` указывает Harbour кодовую страницу/сортировку рабочей области, а `Encoding` в C# управляет передачей текста между .NET и DLL. Для примеров применяются `"UA866"` и `Encoding.GetEncoding(866)`. Не предполагается, что одна настройка автоматически определяет другую. Для записи проверяйте, что текст представим в выбранной кодировке: обычный `Encoding` может заменять неподдерживаемые символы.
