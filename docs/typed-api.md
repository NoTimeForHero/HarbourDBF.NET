# Типизированное чтение DBF

Типизированный слой открывает существующие таблицы, по умолчанию — в совместном режиме только для чтения. Требования к Windows, x86 и нативной DLL такие же, как у остальной библиотеки.

```csharp
using System;
using System.Text;
using HarbourDBF.NET;

public sealed class Person
{
    public int Id { get; set; }
    public string Name { get; set; }
    public DateTime? Birth { get; set; }
}

public sealed class PersonMapping : DbfMapping<Person>
{
    public DbfIndexMapping<Person, int> ById { get; }

    public PersonMapping()
    {
        Field(x => x.Id, "ID");
        Field(x => x.Name, "NAME").TrimEnd();
        Field(x => x.Birth, "BIRTH");
        ById = Index(x => x.Id, "basic_id.cdx", "ID");
    }
}

var mapping = new PersonMapping();
using (var session = DbfSession.Open(@"D:\SampleData"))
using (var people = session.OpenTable("basic.dbf", mapping, "UA866", Encoding.GetEncoding(866)))
{
    var person = people.Index(mapping.ById).FindFirst(2);
    if (person != null) Console.WriteLine(person.Value.Name);
    foreach (var row in people.Scan()) Console.WriteLine(row.Value.Name);
}
```

Модель должна быть классом с публичным конструктором без параметров и публичными свойствами для чтения и записи. Каждое чтение создаёт новый объект. `ReadAt` и `Read` возвращают `null` для отсутствующей или скрытой помеченной записи; `Scan` обходит видимые записи в физическом порядке. Номера записей от 1 до `Int32.MaxValue`. Ссылка принадлежит конкретному открытому экземпляру таблицы и не является постоянным идентификатором: внешний `PACK` или замена файла могут изменить её смысл. Содержимое таблицы не представляет согласованный снимок.

По умолчанию помеченные записи исключаются из чтения, поиска и обхода. При открытии можно передать `deletedRecords: DbfDeletedRecords.Include`, чтобы видеть их и проверять `DbfRecord<T>.IsDeleted`. Политика задаётся для каждого открытого экземпляра таблицы.

Поддерживаются поля `C`/`M` как `string`, `L` как `bool`, целые `N` и служебные `+`/`^` как `int` или `long`, `D`, `@`, `=` как `DateTime?`. Пустая дата или timestamp возвращается как `null`, часовой пояс не преобразуется. Дробные числа, включая `decimal`, и неподтверждённые типы отклоняются при открытии. Строки сохраняют пробелы, если для свойства не задан `TrimEnd()`.

Целое значение, пришедшее через JSON как число с плавающей точкой, принимается только если оно целое и по модулю меньше 2⁵³; иначе чтение завершается ошибкой, поскольку точность исходного числа уже нельзя подтвердить. Для целочисленного представления JSON дополнительно проверяется диапазон свойства.

Индекс описывается после соответствующего поля. Поддерживаются поля `N` с нулевой точностью (`int`) и `C` (`string`, однобайтовая кодировка), возрастающие теги без `FOR` и `UNIQUE`. Для фиксированной ширины можно задать преобразование, например `format: DbfKeyFormat.AllTrim().ThenPadRight(20).Upper()` или `DbfKeyFormat.Str(4)`. Форматирование поискового значения выполняет Harbour с кодовой страницей таблицы; превышение ширины отклоняется. Выражение тега должно совпадать с объявленным после удаления пробелов без учёта регистра. Преобразования с неопределённой конечной шириной пока отклоняются.

Все объявленные файлы открываются при открытии таблицы, а метаданные каждого поискового тега сверяются со схемой и mapping. Дополнительный индексный файл без поискового тега объявляется в конструкторе mapping через `IndexBag("other.cdx")`. `FindFirst`, `FindLast` и `EqualTo` ищут полный ключ, а не префикс. `EqualTo` лениво обходит повторы, `Scan` — записи в порядке индекса; оба допускают вложенные обращения. Повторное перечисление начинает новый обход. При внешних изменениях это не снимок: если последняя возвращённая запись перестала принадлежать ключу, `EqualTo` завершается. Составные ключи, диапазоны и произвольные выражения пока не реализованы. Известные ограничения индексов и открытые вопросы описаны в [плане](plans/2026-11-07_typed-dbf-api.md).

Корень сеанса должен быть абсолютным путём. Относительный DBF разрешается относительно корня, относительный CDX — относительно каталога DBF. Абсолютные пути используются напрямую; неоднозначные пути относительно текущего диска отклоняются. Файл должен существовать. Кодовая страница Harbour (`codepage`) и кодировка обмена с DLL (`encoding`) задаются отдельно. По умолчанию для обмена используется CP866; укажите параметры явно для своего набора данных.

На время типизированной операции библиотека выбирает указанную кодовую страницу Harbour для вычислений VM и затем восстанавливает прежнюю; при пустом `codepage` используется `RU866`, как и при открытии DBF. Неизвестный или некорректный идентификатор страницы отклоняется. Это не определяет автоматически кодировку обмена с DLL.

Для изменения пометки удаления откройте таблицу с `mode: DbfOpenMode.SharedReadWrite` или `ExclusiveReadWrite`, затем вызовите `MarkDeleted(reference)` или `Recall(reference)`. Обе операции делают одну попытку блокировки записи и освобождают её после изменения; повторная установка той же пометки не выполняет запись. `Recall` доступен и для скрытой записи, если ссылка была получена раньше. `DbfLockException` означает, что блокировка не получена. Все сопровождаемые файлы индексов должны быть перечислены в mapping: библиотека не может обнаружить неизвестные внешние CDX. `Commit` не является транзакцией и не обеспечивает откат при ошибке.

`Insert(value)` проверяет доступные значения до добавления и возвращает новую материализованную запись. По умолчанию поля вне mapping остаются со значениями Harbour; `Insert(value, strict: true)` требует, чтобы все поля DBF были отображены, включая служебные. Служебные `+`, `=` и `^` заполняет Harbour, значения модели для них игнорируются. Для `D` принимается `DateTimeKind.Unspecified` без времени, для `@` — тот же `Kind` и точность до миллисекунды. Строки проверяются на представимость и длину в байтах до записи. После успешного добавления последующая ошибка может оставить пустую или частично заполненную запись; автоматического отката нет. Если рабочая область уже удерживает блокировку записи, операция записи завершается ошибкой, не снимая её.

`Update(reference, model => ...)` один раз вызывает callback со свежими данными под блокировкой записи. До первой записи проверяются все изменённые поля; поля вне mapping, служебные и неизменившиеся поля не переписываются. При отсутствии изменений запись и `Commit` не выполняются. Исключение callback или ошибка проверки не начинают запись; после начала записи возможен частичный результат. Обновление помеченной записи запрещено до `Recall`. Повторный вход в типизированный API из callback запрещён. Callback не повторяется автоматически, а ранее прочитанный объект не является проверкой версии.

Типизированный API допускает вызовы с разных потоков: операции последовательно выполняются на внутреннем потоке Harbour VM. Сеанс закрывает принадлежащие ему таблицы, а таблицу можно закрыть раньше. Не используйте низкоуровневый API для изменения глобальных настроек или блокировок одновременно с типизированными операциями. Нельзя вызывать API повторно из callback `Update` либо ждать в нём другую операцию, поставленную в очередь. Настройка очереди, асинхронное ожидание и границы низкоуровневого API описаны в [руководстве по библиотеке](usage.md).
